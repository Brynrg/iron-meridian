# AGENTS.md — Iron Meridian builder rules (read before every change)

Iron Meridian is an IP-clean, browser-native, cold-war RTS built to **mechanical parity with
the 1996 Westwood classic** (see `docs/PARITY_SPEC.md`). It ships to
`speedrungames.net/games/iron-meridian/` through the portal's canonical pipeline
(see `docs/DEPLOYMENT_PATH.md`). `HANDOFF.md` is the current-state document.

## 0. Orientation order
1. This file. 2. `HANDOFF.md` (what is done, what is next, authority granted). 3. `docs/PARITY_SPEC.md`
(the scope). 4. `docs/DEPLOYMENT_PATH.md` (how it ships). Portal contract:
`~/Code/games/speedrungames/AGENTS.md`.

## 1. Deploy (never by hand)
- Every push to `main` auto-deploys via `.github/workflows/deploy.yml` → portal reusable workflow
  → auto-merging portal PR → Netlify. Requires the GitHub repo to exist and hold
  `SPEEDRUNGAMES_TOKEN` (operator-gated; see `docs/DEPLOYMENT_PATH.md` §3).
- Never `cp` `dist/` into the portal, never hand-edit `apps/web/public/games/`, never push to
  portal `main`. Manual fallback is `npm run deploy:portal` (runs the portal ingest, then a PR).
- Keep `vite.config.ts` `base: "./"`. Relative asset URLs only. `npm run lint:paths` enforces it.
- Bump `game.manifest.json#version` on every shippable increment.

## 2. Architecture — the sim/view boundary (most important rule)
- `src/sim/**` is a **pure deterministic simulation**: no DOM, no `Date`/`performance.now`, no
  `Math.random`, no screen/camera/pixel concepts, no `console` in hot paths. Fixed 20 Hz tick
  (`SIM_TICK_RATE` in `src/sim/loop.ts`); per-second rates are divided by `SIM_TICK_RATE`,
  never by 60.
- `src/view/**` owns the canvas, input, camera, audio, wall-clock, and rAF. The view converts
  screen → world **before** queuing a command; sim systems are screen-blind.
- All coordinate conversion goes through `src/sim/coords.ts`. No inline pixel/tile math.
- Commands are the only way the view mutates the sim (`src/sim/commands.ts`). This is what
  makes replays, saves, and lockstep multiplayer possible; do not bypass it.
- Rules data lives in `data/*.json` behind zod schemas in `src/data/`. No magic numbers in
  systems; add a schema field instead.
- One owner per concern: one input handler, one game loop, one spatial index, one pathfinder.

## 3. TypeScript / build hygiene
- Strict TS, `noUncheckedIndexedAccess`-style guarding (`?.`/`??`), no `any`, no unused symbols.
- ESM only: JSON imports use `with { type: "json" }`; no `__dirname` (use `import.meta.url`).
- Remove debug/scratch files before finishing. No `debug-*.ts` left behind.

## 4. Tests and gates
- `npm run verify` = typecheck + lint:paths + unit tests (vitest). `npm test` = Playwright smoke.
  Both must be green before a version bump.
- Unit tests assert magnitude and semantics (credits rose by the expected amount over N ticks),
  not merely `> 0`. Give drip mechanics enough ticks to complete.
- Determinism test: two runs of the same seed + command log must produce identical state hashes.
- Liveness gates (`tests/live/*.spec.ts`) prove the milestone's player-visible promise via
  `window.__debug*` hooks and pixel/screenshot assertions. Playwright clicks use viewport
  coordinates; offset by `canvas.boundingBox()`.

## 5. IP and assets
- Original names, art, audio, text. No ripped sprites, voice lines, music, or trademarks.
- All art is code-drawn or generated by scripts in this repo; anything imported needs a row in
  `ASSETS.md` with licence and source. Declare `expectedAssets` in the manifest when atlases exist.

## 6. Workspace and authority
- Work in place at `~/Code/games/iron-meridian`. Do not move, clone again, or reorganise.
- Superseded code goes to `retired/<date>-<topic>/` with a ledger line in `retired/README.md`;
  never delete in place.
- Implementation, tests, commits, pushes, repo creation, secrets, deploys, and live acceptance
  are separate authorities (`~/.claude/CLAUDE.md`). State each one you exercised in the handoff.
- Use `Pass` / `Fail` / `Not Proven` for operational claims. A green build is not a live game.
